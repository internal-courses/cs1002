A · Inside the Exam

The Python OPPE

OPPE — Online Programming Practice Exam — is the Python programming assessment for IIT Madras B.Sc. students. Each student sits one paper in Wave 1 (basic) and one in Wave 2 (intermediate).

Wave 1 (py11–py14)
Foundational Python
String ops, lists, tuples, basic functions
Wave 2 (py21–py24)
Applied Python
Data analysis, file I/O, complex logic
3 terms · 35 exam sittings · 162 unique questions
Jan–Dec 2025. Variants (paper 1 / paper 2) prevent copying between adjacent seats.
A · Inside the Exam

How the exam works

📝
Save
Students save code anytime. Every version is recorded — giving us a full edit history.
🧪
Public Tests
Run anytime. 2–4 visible test cases. Students see exactly what passes or fails.
🔒
Private Tests
Run only on submit. Hidden from students. 2–4 additional cases that test edge conditions.
The gap between public and private tests is the central tension of this talk. A student can pass all public tests and still fail privately — because public examples aren't the full contract.
Scoring: each test group is worth equal weight. Final score = (groups passed / total groups) × 100. A score of 50 means half the private test groups passed. 100 = full pass on all public + private tests.

def card_to_value_tuple(card: str) -> tuple:
    suit  = card[-1]      # last char: S, H, D, C
    rank  = card[:-1]     # everything before: A, 2…K, 10

    suit_val = suit_values[suit]
    rank_val = (rank_values[rank]
                if rank in rank_values
                else int(rank))

    return (suit_val, rank_val)

def shuffle_sentence(sentence: str,
                     order: tuple) -> str:
    words = sentence.split()
    return ' '.join(words[i] for i in order)

B · Question 4 of 4

Pangram Check

"Heuristics vs. Invariants"

The task: Return True if the input string is a pangram (contains every letter of the alphabet at least once, case-insensitive).
'The quick brown fox jumps over the lazy dog' → True
The invariant
set(text.lower()) must contain all 26 letters
One expression. Checks the actual condition.
The heuristic trap
len(letters) >= 26
A correlation, not a cause. Fails on 'aaa…a' × 26.
1,331 students · 50% full pass ~19 test runs each 36.5% loop-return bug
Question 4 · Student 1 — The Baseline

Zero seconds. Set subset check. Done.

"Build the alphabet as a set. Check if it's a subset of the lowercase input. That's it. The entire invariant in one expression."
The student saw the problem as a membership coverage question. Sets make membership checks O(1). Subsets express "all 26 letters present" directly.
Why issubset is the right tool:
Does every letter in the alphabet appear in the text?
= Is the alphabet set a subset of the text's letter set?
is_pangram.py ✓ 100 
def is_pangram(text: str) -> bool:
    alphabet = set('abcdefghijklmnopqrstuvwxyz')
    return alphabet.issubset(set(text.lower()))

# Or equivalently:
def is_pangram(text: str) -> bool:
    return (set('abcdefghijklmnopqrstuvwxyz')
            <= set(text.lower()))

The Pattern

The four mental models

1. Example Memorizer

Solves the visible world, not the rule

Learns the training data, not the transformation. Passes public tests by hardcoding.

if order == (0,2,1): return 'apple orange banana'
2. Heuristic Guesser

Finds a correlated shortcut instead of the invariant

Spots a feature that correlates with the answer. Public tests agree. Hidden tests don't.

return count >= 26
3. Contract Misreader

Computes the right thing, returns the wrong structure

Intent is correct. Language fluency, data structure, or spec reading is off.

tuple(a, b) · reversed order · no trailing space
4. Regressor

Ends worse than they started

Overwrites a working partial solution while chasing the hidden test. A process failure, not a knowledge gap.

107 events · ends at 0 · had 50 earlier
The Pattern

These aren't Python bugs.

They're epistemological strategies.

"Each one is rational given what the student knows. Your job — whether you're a teacher or a tech lead — is to recognize which strategy is running and name it."
"The junior dev who writes an if/elif for every case isn't lazy. They're listing the universe.
The pull request that adds if input == 'test_case_3' isn't cheating — it's negotiating with the grader.
You've seen all of these. Now you have words for them."
For test design
If public examples only show single-character cards, you've invited the two-character-parser bug. Anti-hardcoding sentinels don't need to be aggressive — they just need to exist.
For code review
When you see a cascade of explicit cases, ask what abstraction the author hasn't seen yet before asking them to rewrite it.
For debugging
The triple-quoted graveyard is in every codebase. The heuristic that passes staging and fails production is a count >= 26 story.
Closing
"The gap between the public tests and the private tests is the gap between the world we can see and the world that actually runs.

Learning Python — learning anything — is mostly about learning to ask: what's on the other side of the tests I can't see yet?"
